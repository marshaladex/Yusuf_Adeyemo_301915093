For concurrency, use two separately opened MySQL clients. Check SELECT CONNECTION_ID() in both. Run B0 → A1 → B1. While B's locking read is waiting, commit A2. Run B2 and capture the latest score of 79 and applied=0, then run A3 to restore 78. If B times out, roll back both sessions, restore score 78 in autocommit and repeat. Keep auto-commit enabled outside explicit transactions. Run each marked block separately.

Atomicity groups the two writes. Constraints enforce local consistency rules. Under READ COMMITTED, B's plain read sees committed data and the primary-key locking read waits for the writer. The conditional update prevents overwriting this demonstrated stale value; applications that must detect intervening changes even when the score returns to the same value should compare a monotonically increasing version. Durability is persistence after successful commit subject to server configuration.
